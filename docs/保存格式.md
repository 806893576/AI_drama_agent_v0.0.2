当前项目的 JSON 持久化主要分两类：

1. 产物文件：由 [ArtifactStore](../services/storage/artifact_store.py) 保存到
   `storage/artifacts/{job_id}/{artifact_type}/{artifact_id}.json`

2. 资产注册表原始文件：由 [AssetStore](../services/storage/asset_store.py) 保存到
   `storage/assets/{job_id}/asset_registry.json`

另外要注意：当前 `input_safety_node` 和 `brief_agent_node` 只把 `input_safety_report`、`creative_brief`、`brief_validation` 放进 Graph State，并创建了 `ArtifactRef`，但没有真正调用 `ArtifactStore.save()`，所以默认不会生成对应 JSON 文件。

**一、所有 Artifact JSON 的通用外壳**

每个由 `ArtifactStore.save()` 保存的 JSON 都是这个结构：

```json
{
  "artifact_id": "story_bible_v001",
  "job_id": "job_xxx",
  "artifact_type": "story_bible",
  "version": 1,
  "content": {},
  "summary": "产物摘要",
  "created_by": "writer.story_bible",
  "parent_artifact_id": null,
  "metadata": {},
  "created_at": "2026-08-14T..."
}
```

字段含义：

- `artifact_id`：产物唯一 ID，通常是 `{artifact_type}_v001`，带命名时是 `{artifact_type}_{name}_v001`
- `job_id`：当前短剧生成任务 ID
- `artifact_type`：产物类型，也是文件夹名
- `version`：版本号，返工后会递增
- `content`：真正的业务内容，每个阶段不同
- `summary`：当前产物的人类可读摘要
- `created_by`：生成该产物的 LangGraph 节点 ID
- `parent_artifact_id`：父产物 ID，用于记录“拆分保存”或返工来源
- `metadata`：扩展元数据
- `created_at`：创建时间

**二、编剧阶段 JSON**

`story_bible/story_bible_v001.json`

`content` 包含：

- `story_bible_id`：故事圣经 ID
- `title`：剧名
- `summary`：较完整的故事设定摘要，不是一句话 logline
- `theme`：主题表达
- `world_rules`：世界观规则
- `core_conflict`：核心冲突
- `timeline_rules`：时间线规则
- `immutable_facts`：不可被后续节点改写的事实

`story_synopsis/story_synopsis_v001.json`

`content` 包含：

- `story_synopsis_id`：故事梗概 ID
- `parent_artifact_id`：父级 Story Bible ID
- `premise`：故事前提
- `protagonist_goal`：主角目标
- `main_story_arc`：完整主线故事发展
- `major_turning_points`：关键转折点
- `major_conflicts`：主要冲突
- `causal_chain`：故事因果链
- `character_arcs`：核心人物变化摘要
- `climax`：最终高潮
- `resolution`：结局收束

`character_bible/character_bible_v001.json`

- `character_bible_id`：人物圣经 ID
- `artifact_type`：固定为 `character_bible`
- `version`：版本号
- `parent_artifact_id`：父级 Story Synopsis ID
- `characters`：人物列表
- `relationships`：人物关系列表
- `character_groups`：人物阵营或功能分组

`characters` 中每个角色采用轻量人物卡，通常包含：

- `character_id`：角色 ID
- `name`：角色名
- `role`：角色功能，如 `protagonist`、`antagonist`、`ally`
- `identity`：一句话身份
- `personality`：性格关键词
- `motivation`：深层动机短段落
- `external_goal`：外部目标
- `internal_goal`：内部目标
- `voice_style`：说话风格
- `visual_keywords`：视觉关键词
- `story_function`：叙事功能
- `character_arc`：人物变化弧线

`relationships` 中每条关系通常包含：

- `relationship_id`：关系 ID
- `source_character_id`：关系来源角色 ID
- `target_character_id`：关系目标角色 ID
- `type`：关系类型，如 `enemy`、`ally`、`family`、`mentor`、`rival`
- `description`：关系说明
- `change_arc`：关系变化方向

分集出场、关系逐集变化、欲望/恐惧/价值观等细拆项不再放在人物圣经第一版中，
而是在分集大纲、剧本或美术资产节点中按需展开。

`episode_outline/episode_outline_v001.json`

- `outline_package_id`：分集大纲包 ID
- `parent_artifact_ids`：依赖的 Story Bible、Story Synopsis、Character Bible ID
- `episodes`：分集大纲列表

每集包含：

- `episode_id`：单集 ID
- `episode_number`：第几集
- `title`：本集标题
- `basic_info`：基础信息，如平台、时长、故事阶段
- `episode_positioning`：本集剧情定位，说明这一集为什么存在
- `opening_hook`：开场 Hook
- `core_conflict`：本集核心冲突
- `key_events`：关键事件
- `characters_and_relationship_changes`：人物参与与关系变化
- `emotional_beats`：本集情绪节点
- `turning_point_and_climax`：转折与高潮
- `ending_and_cliffhanger`：结尾与悬念

`episode_script/episode_script_v001.json`

`content` 是剧集脚本列表，每集包含：

- `episode_id`：单集 ID
- `episode_number`：第几集
- `scenes`：场景脚本列表
- `dialogue`：对白列表

场景脚本包含：

- `scene_id`：场景 ID
- `episode_id`：所属集 ID
- `location_id`：地点 ID
- `time_of_day`：时间段
- `characters`：出场角色 ID
- `action`：动作描述
- `dialogue`：场景内对白
- `emotional_purpose`：情绪目的
- `plot_progression`：剧情推进作用
- `key_props`：关键道具

`dialogue_polish/dialogue_polish_v001.json`

- `polish_package_id`：润色包 ID
- `notes`：润色记录列表，包括对白、角色声口、节奏等修改说明

`writer_package/writer_package_v001.json`

这是给下游使用的轻量汇总包：

- `package_id`：编剧包 ID
- `artifact_ids`：引用到 story_bible、story_synopsis、character_bible、episode_outline、剧本等产物 ID
- `story_bible_summary`：故事圣经摘要
- `story_synopsis_summary`：故事梗概摘要
- `character_ids`：角色 ID 列表
- `episode_ids`：剧集 ID 列表

**三、审核与返工 JSON**

`script_review/script_review_v001.json`

- `review_type`：审核类型，当前为 script
- `report_id`：报告 ID
- `passed`：是否通过
- `overall_comment`：整体评价
- `findings`：问题列表
- `strengths`：优点列表
- `revision_notes`：修改建议

`quality_score/quality_score_v001.json`

- `report_id`：评分报告 ID
- `passed`：是否达标
- `total_score`：总分
- `dimension_scores`：各维度评分
- `weakest_dimensions`：最弱维度
- `threshold`：通过阈值
- `summary`：评分总结

`safety_review/safety_review_xxx_v001.json`

- `report_id`：安全报告 ID
- `layer`：安全审核层级，如剧本文本、镜头视听、视觉 Prompt、最终汇总
- `passed`：是否通过
- `risk_level`：风险等级
- `risk_types`：风险类型
- `findings`：具体问题
- `affected_artifacts`：受影响产物
- `repair_target`：建议返工节点
- `safe_rewrite_suggestions`：安全改写建议

`continuity_review/continuity_review_xxx_v001.json`

- `review_type`：一致性审核类型
- `report_id`：报告 ID
- `passed`：是否通过
- `overall_comment`：整体评价
- `findings`：问题列表
- `checked_character_ids`：检查过的角色 ID
- `checked_scene_ids`：检查过的场景 ID
- `checked_prop_ids`：检查过的道具 ID
- `checked_shot_ids`：检查过的镜头 ID

`repair_plan/repair_plan_v001.json`

- `repair_plan_id`：返工计划 ID
- `issue_type`：问题类型
- `target_node`：要回到的目标节点
- `scope`：返工范围
- `affected_artifacts`：受影响产物
- `keep_unchanged`：必须保持不变的内容
- `instructions`：返工指令
- `reason`：返工原因
- `max_retries`：最大重试次数

**四、导演与视听阶段 JSON**

`director_planning_bundle/director_planning_bundle_v001.json`

- `bundle_id`：导演规划包 ID
- `scene_breakdowns`：场景拆解列表
- `shot_designs`：分镜设计列表
- `performance_direction`：表演调度
- `emotional_rhythm`：情绪节奏

`scene_breakdown/scene_breakdown_v001.json`

- `scene_id`：场景 ID
- `episode_id`：所属集 ID
- `location_id`：地点 ID
- `time_of_day`：时间段
- `characters`：角色 ID
- `key_actions`：关键动作
- `key_props`：关键道具
- `emotional_state`：情绪状态
- `production_notes`：拍摄/制作备注

`shot_list/shot_list_v001.json`

- `shot_id`：镜头 ID
- `scene_id`：所属场景 ID
- `shot_order`：镜头顺序
- `shot_size`：景别
- `duration_seconds`：镜头时长
- `visual_focus`：画面重点
- `camera_movement`：摄影机运动
- `transition`：转场方式

`director_package/director_package_v001.json`

- `package_id`：导演包 ID
- `artifact_ids`：导演阶段产物引用
- `scene_ids`：场景 ID 列表
- `shot_ids`：镜头 ID 列表
- `performance_direction`：表演调度
- `emotional_rhythm`：情绪节奏

`shot_av_planning_bundle/shot_av_planning_bundle_v001.json`

- `bundle_id`：视听规划包 ID
- `shot_intent`：镜头意图
- `camera_plan`：摄影方案
- `lighting_plan`：灯光方案
- `sound_plan`：声音方案
- `vfx_plan`：特效方案

之后会拆分保存为：

- `shot_intent/shot_intent_v001.json`：每个镜头为什么这样拍、表达什么信息/情绪
- `camera_plan/camera_plan_v001.json`：焦段、构图、运动、机位等
- `lighting_plan/lighting_plan_v001.json`：主光、辅光、轮廓光、色温、光比等
- `sound_plan/sound_plan_v001.json`：对白风格、环境音、音效、音乐等
- `vfx_plan/vfx_plan_v001.json`：是否需要特效、屏幕效果、合成说明等

`audiovisual_package/audiovisual_package_v001.json`

- `package_id`：视听包 ID
- `artifact_ids`：视听阶段产物引用
- `shot_ids`：镜头 ID 列表
- `plan_counts`：各类方案数量统计

**五、美术与资产阶段 JSON**

`art_package/art_package_v001.json`

- `art_prompt_package_id`：美术 Prompt 包 ID
- `prompts`：图片生成 Prompt 列表

每个 Prompt 包含：

- `prompt_id`：Prompt ID
- `intended_use`：用途
- `prompt`：正向 Prompt
- `negative_prompt`：反向 Prompt
- `character_ids`：关联角色 ID
- `scene_id`：关联场景 ID
- `prop_ids`：关联道具 ID
- `shot_id`：关联镜头 ID
- `style_keywords`：风格关键词
- `safety_notes`：安全注意事项

`asset_registry/asset_registry_v001.json`

- `registry_id`：资产注册表 ID
- `job_id`：任务 ID
- `characters`：角色资产字典
- `scenes`：场景资产字典
- `props`：道具资产字典
- `shots`：镜头资产字典
- `prompts`：Prompt 资产字典
- `metadata`：扩展信息

同样内容还会额外保存一份原始注册表：

`storage/assets/{job_id}/asset_registry.json`

区别是：`storage/artifacts/.../asset_registry_v001.json` 有 Artifact 外壳；`storage/assets/.../asset_registry.json` 是纯资产注册表内容。

**六、最终交付 JSON**

`final_package/final_package_v001.json`

- `package_id`：最终交付包 ID
- `schema_version`：最终交付包结构版本
- `job_id`：任务 ID
- `source_artifact_ids`：本次汇总使用的 `art_package` 与
  `audiovisual_enhanced_shot_list` 产物 ID
- `art_package`：供下游图像生成使用的精简美术资产信息
  - `style_profile`：统一美术风格
  - `character_assets`：仅保留 `character_name`、`variant`、`prompt`
  - `scene_assets`：用 `scene: ["scene_id_scene_name"]` 表示场景，并保留 `prompt`
  - `prop_assets`：仅保留 `prop_name`、`used_in_scene_ids`、`prompt`
- `audiovisual_enhanced_shot_list`：供下游视频生成使用的最终分镜清单
  - `shot_id`：全局稳定的分镜 ID
  - `scene`：格式为 `["scene_id_scene_name"]`
  - `shot_number`：场景内分镜序号
  - `characters`：格式为 `["character_name_variant"]`
  - `props`：直接保存道具名称列表 `["prop_name"]`
  - `shot_content`：视频生成提示词
  - `continuity`：与前后分镜的连续性说明
- `summary`：最终结果摘要
- `artifact_refs`：所有阶段产物引用
- `acceptance`：最终验收结果
- `sections`：交付包包含哪些模块的说明，例如创作简报、剧本、导演方案、视听方案、美术 Prompt、资产清单、审核报告等

最终分镜中的场景、角色和道具由本地程序按 `shot_id` 查询
`art_package.shot_prompt_plan` 后组装，不再调用 LLM，也不通过提示词文本猜测关联关系。

**七、非阶段产物：数据库 JSON**

工作流还会写入本地 JSON 数据库：

`storage/database/jobs.json`

每个任务记录包含：

- `job_id`：任务 ID
- `user_request`：用户原始输入
- `status`：任务状态
- `final_message`：最终返回消息
- `artifact_ids`：关键产物 ID 汇总
- `event_count`：运行事件数量
- `created_at`：创建时间
- `updated_at`：更新时间

`storage/database/evaluations.json`

每条评估记录包含：

- `evaluation_id`：评估 ID
- `job_id`：关联任务 ID
- `scores`：评分字典
- `passed`：是否通过
- `summary`：评估总结
- `created_at`：创建时间

当前最值得补的一点是：输入安全、需求分析、Brief 校验现在还没有真正落盘，只是放在 state 里。后续如果你希望全链路可追溯，建议把这三个也统一接入 `ArtifactStore.save()`。
